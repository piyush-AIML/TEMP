    16→## 1. Brand & Product Analysis
    17→
    18→### 1.1 What Educraft actually is
    19→A global digital education platform unifying **5 distinct verticals** under one trust umbrella — not a single-subject course site. The website's core job is therefore **twofold**: (a) build institutional/parental trust fast, because the offer is broad and could otherwise read as unfocused, and (b) route each visitor to *their* vertical quickly, because a parent looking for NEET coaching and a school evaluating inclusive-ed partnerships are having completely different conversations on the same site.
    20→
    21→### 1.2 Emotional strategy → UI decision mapping
    22→The brand doc names 5 target emotions. Each has a direct, concrete design consequence — not just a mood:
    23→
    24→| Emotion | UI consequence |
    25→|---|---|
    26→| Trust | Indigo-led navbar/footer, real institutional-feeling structure (clear nav, no dark patterns), no stock "smiling stock-photo student" clichés |
    27→| Hope | Warm gold used *only* for achievement/success moments (badges, CTA accents) — scarcity makes it mean something |
    28→| Belonging | Inclusive Education gets equal visual weight to NEET/JEE — no vertical is styled as the "real" product and others as filler |
    29→| Achievement | The gold accent + subtle upward-motion micro-interactions on stat/achievement elements |
    30→| Calm Confidence | Generous whitespace, soft shadows (never harsh drop-shadows), restrained motion — the site should never feel like it's trying to hype the visitor |
    31→
    32→### 1.3 Archetype blend → tone
    33→**Sage + Caregiver + Creator.** In practice: copy explains *why*, not just *what* (Sage); copy is warm and reassuring, never salesy (Caregiver); the site should feel like it's building something specific for *this* learner, not selling a generic course catalog (Creator). Concretely, avoid: exclamation-heavy CTAs, countdown/urgency tactics, "🔥 limited seats!" energy. This is a counselling-adjacent brand, not a flash-sale brand.
    34→
    35→### 1.4 Voice: do / don't (from brand doc §8, applied literally)
    36→- ✅ "Every student deserves a learning path that understands their strengths."
    37→- ❌ "Join our course now!"
    38→- Encouraging, not preachy · Expert, not academic-heavy · Warm, not childish · Global, not region-specific.
    39→
    40→### 1.5 Visual clichés to explicitly avoid
    41→From the brand doc itself: graduation caps, shields, mascots, cartoon children, generic stock "e-learning" iconography, excessive 3D. **Additionally**, avoid the three looks that currently read as "default AI-generated design": warm cream background + serif + terracotta accent; near-black background + single neon accent; broadsheet/newspaper hairline-rule layout. Educraft's actual palette (indigo/teal/gold on white/sky-blue) is naturally distinct from all three — stay inside the brand palette rather than drifting toward any of them for "safety."
    42→
    43→### 1.6 The 5 verticals (source of truth — used throughout)
    44→
    45→| # | Course | Pillar (brand §8) | Slug |
    46→|---|---|---|---|
    47→| 1 | Linguistics | Learn | `linguistics` |
    48→| 2 | Inclusive Education | Include | `inclusive-education` |
    49→| 3 | Psychological Counseling & Wellbeing | Thrive | `wellbeing-counseling` |
    50→| 4 | AI and Digital Technologies | Achieve | `ai-digital-tech` |
    51→| 5 | NEET & JEE Preparation | Excel | `neet-jee` |

    55→## 2. Design System (single source of truth — build once in Stage 0, reference forever after)
    56→
    57→### 2.1 Color tokens
    58→Base 5 colors are fixed by the brand doc. Neutral/text scale below is a necessary, brand-consistent *extension* (the brand doc gives hero colors, not a full UI-ready neutral scale — pure indigo body text at small sizes fails contrast/readability, so a near-navy ink is used for text instead).
    59→
    60→```js
    61→// tailwind.config.js -> theme.extend.colors
    62→colors: {
    63→  indigo:  { DEFAULT: '#1E2A78', dark: '#141D57', light: '#3B4896' }, // trust, authority, nav/footer
    64→  teal:    { DEFAULT: '#00B3B8', dark: '#00898D', light: '#3FCBCF' }, // innovation, links, secondary CTA
    65→  gold:    { DEFAULT: '#F4B942', dark: '#D89F2B', light: '#F8CD73' }, // achievement — use SPARINGLY, accents only
    66→  sky:     '#EAF6FF',   // section background tint
    67→  white:   '#FFFFFF',
    68→  ink:     '#12172E',   // body text (near-navy, not pure black — stays in brand family)
    69→  slate:   '#5B6478',   // secondary/muted text
    70→  border:  '#E4E9F2',   // dividers, card borders
    71→}
    72→```
    73→**Usage rule:** indigo and white/sky carry ~80% of the UI (trust, calm). Teal is the interactive/secondary color (links, hover states, secondary buttons). Gold appears only on achievement moments — success states, "Excel"/"Achieve" pillar accents, primary CTA button — never as a background flood.
    74→
    75→### 2.2 Typography
    76→Two roles, both already brand-recommended fonts — no drift from the brief:
    77→- **Display** (headlines, hero, section titles): **Sora**, weights 600/700. Geometric, rounded, carries the "crafted compass" personality.
    78→- **Body/UI** (paragraphs, nav, forms, buttons): **Manrope**, weights 400/500/600. Same geometric family-feel, higher readability at small sizes.
    79→- **Eyebrows/labels** (pillar tags, form labels): Manrope 600, uppercase, `letter-spacing: 0.08em`, `font-size: 0.75rem` — no third typeface needed.
    80→
    81→Type scale (rem, desktop → mobile shrinks via `clamp()`):
    82→`h1: clamp(2.25rem, 4vw, 3.5rem)` · `h2: clamp(1.75rem, 3vw, 2.5rem)` · `h3: 1.5rem` · `body: 1rem/1.7` · `small: 0.875rem`
    83→
    84→### 2.3 Layout & structure
    85→- Radius: `rounded-2xl` (1rem) as the default card/button/input radius — matches brand's "rounded edges for friendliness."
    86→- Shadows: soft only — `shadow-[0_8px_30px_rgba(30,42,120,0.08)]`, never harsh/black drop shadows (supports "calm confidence").
    87→- Section rhythm: `py-24` desktop / `py-14` mobile, max content width `1200px`, `px-6` gutters.
    88→- **No decorative numbered markers (01/02/03) on the 5 course cards** — the verticals are not a sequence, presenting them as one implies a false hierarchy/order. Use icon + pillar label instead.
    89→
    90→### 2.4 Signature element: The Pathway Motif
    91→Pulled directly from the brand doc's own symbolism (§5 "interconnected pathways," §10 "global orbit"), turned into one real, reused UI element instead of generic decoration:
    92→
    93→A thin (1.5px) teal/indigo line-and-node motif, arranged as an **orbit/ring** (not a left-to-right timeline — avoids implying the 5 verticals are sequential steps):
    94→- **Hero:** faint animated SVG — the path draws itself once on load (`stroke-dashoffset` animation, ~1.2s, runs once), sitting behind the headline at low opacity. Skips animation entirely under `prefers-reduced-motion`, just renders static.
    95→- **Courses Overview section:** the 5 course cards sit around a faint circular orbit line connecting them — visualizing "one connected ecosystem," not a 5-step funnel.
    96→- **Footer:** the same ring, large-scale, very low opacity, as background texture.
    97→
    98→This is the *one* place the design gets expressive — everything else stays quiet and disciplined around it.
    99→
   100→### 2.5 Iconography
   101→`lucide-react` (lightweight, line-based, zero cliché risk). Mapping:
   102→| Course | Icon |
   103→|---|---|
   104→| Linguistics | `Languages` |
   105→| Inclusive Education | `HeartHandshake` |
   106→| Wellbeing & Counseling | `Sparkles` |
   107→| AI and Digital Technologies | `BrainCircuit` |
   108→| NEET & JEE | `Atom` |
   109→
   110→### 2.6 Motion principles
   111→Deliberate, not scattered. Scroll-reveal (fade + 12px slide-up, one shared `useReveal` hook via `IntersectionObserver` — no animation library dependency needed). Card hover: subtle lift (`translateY(-4px)`) + shadow deepen, 150ms. Hero pathway draw: once, on load. Nothing else animates. Always respect `prefers-reduced-motion: reduce`.

   228→## 4. Enquiry Form System Spec
   229→
   230→**Two modes of one component — this is the exact mechanism satisfying both form requirements from the brief:**
   231→
   232→- **`mode="general"`** (landing page popup, floating CTA): includes a "Which course are you interested in?" select, populated from `courses.js`. Used when intent is unknown.
   233→- **`mode="locked"`** (embedded inline on every course page, near the bottom): course select is hidden; a fixed, visibly-stated field shows "Enquiring about: **[Course Name]**"; the slug is passed as a hidden form value. No way to change course from this instance — that's the whole point of "only take enquiry for that particular course."
   234→
   235→### Fields
   236→Full name* · Email* · Phone* · Course (select — general mode only, else locked+hidden) · Preferred contact time (optional) · Message (optional, textarea) · Consent checkbox* ("I agree to be contacted about this enquiry")
   237→
   238→### Validation
   239→Required-field check, email regex, phone digit-length check (10+ digits), consent must be checked before submit is enabled. Inline error text under each field, not just a top-of-form banner.
   240→
   241→### Submission handling (demo-appropriate, real backend deferred)
   242→Centralize submission in one file so the actual provider is a one-line swap later:
   243→```js
   244→// src/api/enquiry.js
   245→export async function submitEnquiry(payload) {
   246→  // Demo default: Formspree (free, no backend needed, emails actually arrive)
   247→  // Replace YOUR_FORM_ID at https://formspree.io before the client demo.
   248→  const res = await fetch('https://formspree.io/f/YOUR_FORM_ID', {
   249→    method: 'POST',
   250→    headers: { Accept: 'application/json' },
   251→    body: JSON.stringify(payload),
   252→  });
   253→  if (!res.ok) throw new Error('Submission failed');
   254→  return res.json();
   255→}
   256→```
   257→UI: submit → loading state on button → success state ("Thanks — we'll be in touch within 1 business day.") replacing the form, or inline error state with a retry option on failure.
   258→
   259→### Accessibility (non-negotiable, both modes)
   260→Every input has a real `<label>`, modal traps focus and returns it to the trigger button on close, `Esc` closes the modal, error messages are associated via `aria-describedby`.
